# Purpose

This glossary provides a quick reference to commonly used terms within the Data Analytics Project Methodology (DAPM).

Detailed definitions and official terminology are maintained in **TERMINOLOGY.md**.

---

| Term | Short Definition |
|------|------------------|
| Business Problem | The challenge or opportunity the analytics project aims to address. |
| Stakeholder | A person or group that uses the results of the analysis. |
| Business Requirement | Information required to support business decisions. |
| Metric | A measurable value describing business performance. |
| KPI | A metric directly linked to a business objective. |
| Data Discovery | Identifying and understanding available data sources. |
| Data Profiling | Examining the characteristics and quality of raw data. |
| Data Cleaning | Correcting issues identified during data profiling. |
| Data Validation | Verifying that cleaned data satisfies business rules. |
| EDA | Exploring validated data to discover analytical patterns. |
| Observation | A factual statement supported directly by the data. |
| Business Insight | An explanation describing why observations matter. |
| Recommendation | A proposed business action supported by analytical evidence. |
| Visualization | A graphical representation of data used to communicate findings. |
| Evidence | Data supporting observations, insights, and recommendations. |
| Deliverable | An output produced during a DAPM phase. |
| Executive Summary | A business-focused summary prepared for decision-makers. |
| Project Summary | A concise summary describing the completed analytics engagement. |
| Validation Project | A practical project used to evaluate and improve DAPM. |
| Framework | The complete DAPM system of documents, templates, and methodology. |
| Methodology | The structured workflow used to execute analytics projects. |

---

For complete definitions and official terminology, refer to **TERMINOLOGY.md**.
